# Black-box 游戏社区 — 分期概要设计文档

> 版本:v1 · 日期:2026-06-17 · 状态:待评审

## 一、背景与目标(Context)

当前项目前端是"游戏社区"皮肤,后端却是一个**功能残缺的通用帖子系统**。经审查,核心社交功能(评论、点赞、收藏、上传、发帖入口)全部是假数据或未实现,数据表已建好但缺接口;同时存在假发布时间、畸形头像 URL、标签栏失效等 bug,以及 AI 接口裸奔、密钥弱等隐患。

**本次目标(已确认的方向):**
- **定位**:作品集 / 可演示项目 —— 功能完整、界面真实、能流畅演示,消除一切假数据和明显 bug,但不要求生产上线级运维。
- **首期重点**:先补齐核心社交功能,让它"像个真社区"。
- **主题收敛**:真正做成**游戏社区** —— 新增 `Game` 表,帖子关联具体游戏;内容类型复用 `Tag`(攻略/评测/求助/讨论),首页按 Tag 筛选。
- **AI 精简**:只保留 **游戏 AI 助手(聊天)** 和 **语义搜索**,共享一套"帖子标题向量"基础设施;**砍掉** DALL-E 头像生成、RAG(开发文档)、Git commit 生成。

## 二、设计原则与范围

| 原则 | 说明 |
|------|------|
| 复用优先 | 复用已有的 `JwtAuthGuard`、JWT/bcrypt 体系、axios token 刷新、Zustand store 模式、余弦相似度逻辑、`PostItem` 首字母 fallback 头像;`multer` 随 `@nestjs/platform-express` 内置(`FileInterceptor` 可用,或补 `@types/multer`) |
| 真实数据 | 删除所有 mock/`Math.random()`/写死数据,改为真实接口驱动 |
| 演示友好 | 提供 seed 脚本造游戏+帖子+评论演示数据;补 loading/error 态 |
| 主题聚焦 | 一切围绕游戏社区;砍掉跑题的 AI demo(Git/RAG/头像生成) |

**明确不做(本轮范围外)**:HttpOnly Cookie 改造、token 吊销/轮换、对象存储、helmet/CSP 等生产级加固(后续按需轻量补,但不作为作品集重点)。

## 三、数据模型变更(Prisma)

> 文件:`backend/backend/posts/prisma/schema.prisma`,配套 `npx prisma migrate dev`

**1. 新增 `Game` 表**
```prisma
model Game {
  id          Int      @id @default(autoincrement())
  name        String   @unique @db.VarChar(255)   // 原神 / 黑神话:悟空
  cover       String?  @db.VarChar(255)           // 封面图 filename
  description String?  @db.Text
  createdAt   DateTime @default(now()) @map("created_at") @db.Timestamptz(6)
  posts       Post[]
  @@map("games")
}
```

**2. `Post` 表增补字段**(解决假时间 + 游戏关联 + 标题向量 + 浏览量)
```prisma
model Post {
  // ...现有字段...
  createdAt      DateTime  @default(now()) @map("created_at") @db.Timestamptz(6) // 替代伪造的 publishedAt
  updatedAt      DateTime  @updatedAt @map("updated_at") @db.Timestamptz(6)
  viewCount      Int       @default(0) @map("view_count")                        // 替代 Math.random()
  gameId         Int?
  game           Game?     @relation(fields: [gameId], references: [id], onDelete: SetNull)
  titleEmbedding Json?     @map("title_embedding")                               // 标题向量(语义搜索 + AI 助手共用)
  @@index([gameId])
}
```

**3. `Tag` 语义改造(无结构变更)**:把 Tag 数据从"游戏名"改为**内容类型**(攻略、评测、求助、讨论…),通过 seed 重建。`PostTag` 多对多关系不变。首页筛选改为按内容类型 Tag。

**4. 已就绪、仅补接口的表**:`Comment`(含 `parentId` 自引用,支持嵌套回复)、`UserLikePost`、`Avatar`、`File` —— 结构无需改动。

## 四、分期规划总览

| 期 | 主题 | 产出 | 价值 |
|----|------|------|------|
| **一期** | 前端骨架 + 数据奠基 | Game 表 / Post 增补字段 / Tag 语义重建;App Shell + 侧边导航三段式响应式骨架;路由结构与路由级保护 | 浇好最终骨架地基,后续页面只建一次 |

## 五、一期:前端骨架 + 数据奠基

本期只浇地基,不做业务功能:把数据模型和前端最终骨架(布局 + 路由)一次性建好,后续业务页面直接长在最终骨架上。

**数据库**:落地第三节的 `Game`、`Post` 增补字段、`Tag` 语义重建 migration。

**导航骨架(App Shell + 侧边导航)**:实现 App Shell + 侧边导航组件,落地桌面 / 平板 / 手机三段式响应式骨架(见 11.3)。**现有移动优先布局(Header + BottomNav)整体弃用、不保留**,直接以桌面侧边栏 + 移动底 tab 的最终骨架为唯一布局。

**路由结构与路由保护**(依附于导航结构,与导航骨架同期建立):
- 路由结构随侧边导航一并搭好。
- 修 `App.tsx` 的 `needsLogin`(现为 `['/mine','/order','/chat']`),直接基于侧边栏结构重配,覆盖 `/chat`、发帖页、`/mine`;同时清理两类废弃项 —— 删除 `needsLogin` 中无对应页面的数组项 `/order`,并删除已废弃的路由 `/rag`、`/git`(它们本不在 `needsLogin` 内,是无保护的遗留路由);守卫改为路由级包裹,而非 `<Routes>` 外的 useEffect 兜底。
- 本期按**最终路由形态**把路由表与保护规则一次配好,但此时这些受保护页以**占位组件**顶着,真实页面由后续期次逐步填入:发帖页 / 详情 / `/mine` / 登录注册页见二期,`/chat` 等 AI 页见三期。即一期保护的是已配好的占位路由,而非已完成的页面——这与"页面内尚无真实业务功能"的空壳定位自洽。

**本期产出定位**:一个可运行的"空壳"应用 —— 侧边栏在、路由通、三断点不塌、登录态可拦,但页面内尚无真实业务功能。这是后续所有前端工作的稳定地基。

**一期验收**:导航骨架就位;三段式响应式在桌面/平板/手机三个断点表现正确、移动端底 tab 正常;路由结构通、路由保护基于侧边栏结构生效,未登录访问受保护页被拦。**不含具体业务功能验收**(业务功能见二期)。

## 七、三期:游戏化 + AI 精简

**标题向量基础设施(两个 AI 功能共用)**:
- 发帖/改帖时,用 embedding 模型对**标题**生成向量,存入 `Post.titleEmbedding`。
- 复用 `ai.service.ts` 现有 `cosineSimilarity` 逻辑,但数据源从静态 `posts-embedding.json` **改为从库动态加载**(服务启动载入内存 + 新帖增量更新),删除对 build 产物路径的脆弱依赖。
  > 三期细化(2026-06-25):落地采用**"搜索时查库 + 内存余弦"**(见 `03-phase3-ai-gamification.md` §3.3 方案 B);"启动载入内存 + 增量"作为数据量大增后的优化留后续。此处以 `03-phase3` 为准。

**语义搜索改造**:`GET /api/ai/search?keyword=` → query 向量化 → 与所有帖子标题向量算余弦 → 返回 top N 帖子(随发帖自动更新,不再依赖预生成文件)。

**游戏 AI 助手(聊天)**:`POST /api/ai/chat` → 用户提问向量化 → 检索命中的站内帖子(标题向量)→ 把命中帖子作为上下文喂给 DeepSeek → 流式回答并**引用站内帖子**。同时修正现状 SSE 格式与 `@ai-sdk/react` 协议不一致的问题。

> AI 接口(chat/search)在实现时**同步加** `JwtAuthGuard`(复用现有守卫),不留到最后统一加。

**砍掉**:`GET /api/ai/avatar`(DALL-E)、`POST /api/ai/rag`、`POST /api/ai/git` 及对应前端页(`/rag`、`/git`)与 store。

**游戏化前端**:游戏专区/按游戏筛选(首页主筛选仍按内容类型 Tag,游戏维度作为补充筛选或专区);可选游戏详情页(列出该游戏下帖子)。

**三期验收**:发新帖后立即可被语义搜索命中;向 AI 助手问"黑神话有什么攻略",回答能引用站内真实帖子;匿名调 AI 接口被拒;`/rag`、`/git` 入口已移除无残留。

### 11.2 组件体系

- **全局组件**(对应未来 `components/ui`):按钮(primary/secondary/ghost/sm/block)、Pill 标(accent/warm + 5 内容类型 + soft)、标签筛选 chip、帖子卡、头像(三尺寸 + 渐变底)、统计按钮(含 liked)、轮播(dot/arrow)、面板/磁贴、表单字段(input/textarea/select)、搜索框、侧边导航、顶栏、下拉刷新、标题层级。
- **页面级组件**:评论项/回复框、聊天气泡(ai/me)+ 快捷 chip + 会话项、发帖封面位/标题输入/标签选择/编辑器+实时预览、分段控件 seg、文章行 prow、资料头 profile-hero/数据墙/快捷入口、登录注册(品牌面板/seg 切换/密码显隐/密码强度条/复选)、搜索摘要 + 关键词高亮。
- 每个组件以"职责 + 变体/状态"概要描述(不含像素),详细设计阶段再展开为组件清单与 API。
- **复用与扩展原则**:
  1. 全局组件单一来源,页面级组件随页面就近;落地映射到 shadcn/ui + Tailwind v4 `@theme`。
  2. 状态统一用 `data-state`(决议 C),不再混用 `.active`/`.on`。
  3. 变体走语义类/CSS 变量,禁止内联硬编码颜色/阴影/间距(决议 A/B/D/F)。
  4. 新组件优先**组合现有 token 与基础组件**,不另起样式体系。

- **页面列表**(原型 → 应用),各页给"信息架构概要"并引用原型文件:

### 11.4 交互规范

- **导航**:主导航 4 项(首页 / 攻略助手 / 发帖 / 我的,决议 K 保持),二级页靠页面内入口;移动端底部 tab。

### 11.6 详细设计待办
